# Spotify to YouTube Music

Copy the requested collection while leaving Spotify unchanged. Resolve ownership and playlist scope from the request before destination edits. Liked Songs is a separate scope item; copy it into a named playlist unless the user specifically requests YouTube Music likes. Use a private destination by default unless the user chooses another visibility.

Use available authorized connectors when they expose the needed metadata and operations. Otherwise use the user's selected browser and supported browser tools. Read the current browser documentation before automation. Do not extract session tokens, scrape hidden application state, or introduce an unofficial API client to bypass the browser workflow.

Read [references/browser-workflow.md](references/browser-workflow.md) for the observed UI, picker handling, and recovery techniques. These are adaptable examples, not stable selectors or APIs.

## Plan and match

1. Inventory each requested source playlist, owner, count, ordering, and every occurrence. Read virtualized rows by displayed position; scroll and merge by position until the displayed total reconciles. Capture title, Spotify track link, artists, album, duration, and version qualifications. Record unavailable rows rather than searching empty titles.
2. Inventory destination names before creating anything. Distinguish existing user playlists from previous copies. Resume a copy only when its manifest and destination identity establish that it belongs to this transfer; avoid duplicate copies on retry.
3. Search YouTube Music's Songs catalog. Compare title, credited performer, album, duration, language, and version. Preserve lo-fi producer, remix, male/female, radio edit, live, instrumental, explicit/clean, slowed or sped-up distinctions. Never silently substitute an ordinary recording for a requested lo-fi version, or a cover for an original. Official catalog remixes/covers can qualify when that is the requested source version and the user's restrictions permit them.
4. Verify release provenance alongside recording identity. Auto-generated results with both `Provided to YouTube by` and `Auto-generated by YouTube`, consistent credits, and label/release information provide strong evidence. An official artist/label upload can also qualify when authenticity and recording version are established. A title match, a Topic-looking channel name, or view count alone is insufficient. Metadata is evidence, not proof of licensing for every upload. Exclude fan uploads and anything with conflicting or unverifiable provenance.
5. Use duration as corroboration: small rounding/silence differences may be acceptable when other evidence agrees. Version-sensitive edits deserve closer comparison. Do not impose a universal duration tolerance or let duration override conflicting artists/version labels. Spelling/transliteration aliases require evidence from the credited release.
6. Reuse a previous verified match for the same Spotify recording if its evidence remains applicable. A recording can have several legitimate catalog IDs from different releases; retain that relationship rather than assuming one possible ID. Keep uncertain matches unresolved with a specific reason.

## Copy and recover

Prepare a match plan before additions when feasible, then add verified entries in source order. Preserve repeated occurrences; ordinary Save-to-playlist flows may silently deduplicate. The same-account YouTube editor's Add videos picker can preserve duplicates when the browser exposes that workflow. Verify the actual count after using it.

Work in small bounded batches and save a local manifest after each confirmed mutation. Store destination identity, source positions, chosen catalog IDs, match evidence, unresolved reasons, and actual saved rows. A click attempt or toast for another destination is not confirmation.

After a timeout or interruption, read the destination before retrying. Reconcile ordered video IDs and occurrence counts with the manifest; the last action may have succeeded without a checkpoint. Refresh stale handles and indices. If an operation continues failing after refreshed state and one supported alternative, checkpoint and report the concrete blocker rather than retrying blindly.

For late matches, restore source order using visible reorder controls. Repeated IDs require occurrence-aware reconciliation. Avoid destructive recreation or source deletion as a recovery method.

## Verify and report

Read all actual destination entries, excluding recommendation rows. Compare ordered video IDs against the approved match plan, including duplicates. Reconcile source count as copied + unresolved + unavailable. Mark each playlist complete independently; one verified playlist does not establish completion of a requested library.

Use the schema in [references/manifest.md](references/manifest.md), then run:

```sh
python3 scripts/audit_manifest.py /absolute/path/manifest.json
```

This checks counts, order, and occurrence identity. It does not verify music provenance or live account state; establish those through the source UI/connector.

Deliver destination links, copied/source counts, skipped titles/reasons, and material limitations. Save a real browser screenshot and embed it when the browser tool requires proof of website changes. Keep per-track evidence in a local HTML/JSON report. Do not include personal manifests, screenshots, playlist IDs, or authentication/session data in a published copy of this skill.
